# Cafe Quest — 제품 요구사항

- 버전: v0.2
- 작성일: 2026-11-17 (Asia/Seoul)
- 상태: 검토용 초안, 구현 전
- 대상: 단일 오프라인 카페에서 운영하는 모바일 웹서비스
- 제품명: Cafe Quest는 임시 이름

## 1. 제품 개요

실제 카페를 닮은 2D 맵에서 내 캐릭터로 머물고, 방문 퀘스트를 수행해 코인을 모으며, 캐릭터를 꾸민다. 다른 손님에게는 자신이 선택한 정보만 공개한다.

방문할 때마다 작은 발견과 수집의 즐거움을 제공해 재방문 동기와 매장에 대한 애착을 만든다. 실제 메뉴, 가구, 식물, 계절 변화가 디지털 콘텐츠와 연결된다.

### 목표

- 반복 방문에도 새로운 즐거움을 제공한다.
- 혼자 온 손님도 대화 부담 없이 매장에 참여할 수 있게 한다.
- 카페 고유의 공간과 메뉴를 기억에 남는 수집 요소로 만든다.
- 바쁜 시간에도 직원의 추가 업무가 적어야 한다.

### 첫 출시에서 제외

자유 채팅, 친구·팔로우, 공개 방문 이력, 경쟁 순위, 현금 구매·환전·양도, 실제 할인 교환, POS 자동 연동, 좌석 예약, 3D 자유 이동, 다지점 운영. 가벼운 반응과 공동 퀘스트는 후속 단계다.

## 2. 사용자와 핵심 흐름

| 사용자 | 필요 |
| --- | --- |
| 첫 방문 손님 | 설명 없이 시작하고 첫 보상 받기 |
| 단골 | 누적 방문과 수집에 의미 부여 |
| 혼자 온 손님 | 공개·교류를 강요받지 않고 참여 |
| 교류를 원하는 손님 | 취향과 현재 상태를 선택적으로 표현 |
| 직원·운영자 | 빠른 승인과 실수 복구, 간단한 콘텐츠 관리 |

핵심 흐름: 매장 QR 접속 → 캐릭터 생성 또는 복원 → 방문 인증 → 카페 맵 → 퀘스트 완료 → 보상 수령 → 아이템 구매·착용 → 퇴장 또는 체류 만료.

대표 사례: 손님이 방문 인증 후 새 화분을 찾는 퀘스트를 수행한다. 코인을 받아 매장의 머그컵을 닮은 소품을 구매한다. 원한다면 다른 손님에게 ‘오늘 고른 음료: 라테 / 독서 중’을 공개한다.

공개 참여와 교류는 보상 획득의 조건이 아니다. 손님이 없는 시간에도 기본 경험을 완주할 수 있어야 한다.

## 3. 우선순위와 MVP

P0는 파일럿 전 필수, P1은 파일럿 이후 검토 항목이다.

| 영역 | P0 | P1 |
| --- | --- | --- |
| 계정 | 게스트 시작, 재접속 복원, 계정 연결·복구 경로 | 추가 로그인 제공자 |
| 맵 | 실제 매장을 닮은 2D 맵, 구역 선택, 오브젝트 | 계절 애니메이션, 개인 공간 |
| 방문 | 인증, 재입장, 직접 퇴장, 서버 기준 만료 | 주문별 자동 인증 |
| 퀘스트 | 방문·탐색·자기 입력·구매·누적 유형 | 공동 퀘스트 |
| 보상 | 코인 원장, 중복 지급 방지, 상점, 착용 | 컬렉션·한정 이벤트 확대 |
| 손님 공개 | 항목별 설정, 미리보기, 공개 철회 | 수신 동의형 반응 |
| 운영 | 승인, 콘텐츠·아이템 관리, 조정, 이용 제한 | 다지점·상세 분석 |

기술 스택은 아직 확정하지 않는다. 다중 사용자 상태와 보상 검증은 서버가 필요하며, 로컬 저장만으로 실제 서비스를 운영하지 않는다.

## 4. 기능 요구사항

### 4.1 접속과 계정

- 앱 설치 없이 QR로 접속한다.
- 닉네임과 기본 캐릭터를 선택한다. 닉네임은 중복될 수 있으며 내부 식별자는 별도로 둔다.
- 게스트는 같은 브라우저에서 복원한다. 브라우저 데이터 삭제·기기 변경 시 복구 제한을 안내한다.
- 지속 수집을 원하는 손님에게 계정 연결을 제공하며 기존 코인과 아이템을 보존한다.
- 연결 대상 계정에 이미 데이터가 있으면 자동 합산하지 않는다. 소유권 확인과 이전 규칙을 확정해야 한다.
- 로그아웃, 계정 삭제 및 데이터 처리 안내를 제공한다.
- 운영자 로그인과 권한은 손님 계정과 분리한다.

### 4.2 실제 매장 맵

- 사진·평면도를 바탕으로 출입구, 카운터, 창가 등 주요 공간을 2D로 표현한다.
- 자유 이동 대신 구역을 눌러 머무는 방식으로 시작한다.
- 퀘스트 오브젝트, 내 캐릭터, 공개 참여 중인 손님을 표시한다.
- 기본 위치는 실제 좌석과 무관한 공용 공간이다. 실제 좌석 연결은 별도 동의로만 제공한다.
- 캐릭터 위치는 예약·좌석 점유를 의미하지 않으며 화면에서 이를 안내한다.
- 혼잡 시 캐릭터를 구역별로 묶는다. 모든 캐릭터를 한 번에 그릴 필요는 없다.
- ‘맵 참여 중 N명’으로 표시한다. 실제 매장 인원이나 혼잡도처럼 표현하지 않는다.

### 4.3 방문 인증과 체크아웃

접속, 방문 기록, 체류, 공개 상태를 구분한다.

| 개념 | 의미 |
| --- | --- |
| QR 접속 | 서비스 열기. 방문 인증을 의미하지 않음 |
| 방문 기록 | 유효한 인증과 보상 이력을 보존하는 기록 |
| 체류 세션 | 유효 시간이 있는 현재 참여 상태 |
| 맵 공개 | 유효 체류와 본인 공개 동의를 모두 충족한 상태 |

- 고정 QR은 접속용으로만 쓴다.
- 방문 인증은 날짜별 매장 코드 또는 직원 확인을 후보로 둔다. MVP 인증 방식은 개발 전 확정한다.
- 날짜별 코드도 공유될 수 있음을 전제로 보상 가치를 낮게 시작하고 과도한 중복 사용을 제한한다.
- 기본 방문 보상은 계정·매장·영업일당 한 번이다. 재입장은 가능하지만 추가 보상은 없다.
- 계정당 활성 체류는 하나다. 여러 탭·기기에서 같은 세션을 사용하며 퇴장·공개 해제는 전체에 반영한다.
- 체류 유효 시간은 최초 90분을 제안한다. 매장 체류 데이터로 조정한다.
- 앱 사용 중 만료 전에 ‘아직 카페에 계신가요?’를 묻고 명시적 확인으로 연장한다.
- 웹 종료, 백그라운드 전환, 화면 잠금, 연결 끊김만으로 즉시 퇴장하지 않는다.
- 클릭·네트워크 연결이 있다는 이유만으로 체류를 자동 연장하지 않는다.
- 미연장 만료 시 서버 기준으로 공개를 종료한다. 백그라운드 알림 도착을 전제로 하지 않는다.
- 만료 후 복귀 시 현재 방문 여부를 다시 확인하고 필요 시 재인증한다.
- 직접 나가기, 운영자 종료, 영업 종료 시에도 공개를 종료한다.
- 만료 시간은 실제 퇴장 시각으로 분석하거나 다른 손님에게 제공하지 않는다.
- 실제 퇴장 탐지가 정확하지 않으므로 ‘매장에 반드시 있음’을 보장하는 표현은 쓰지 않는다.

### 4.4 퀘스트

| 유형 | 예시 | 확인 |
| --- | --- | --- |
| 방문 | 오늘 카페 방문 | 유효 방문 인증 |
| 탐색 | 맵에서 새 화분 찾기 | 오브젝트 선택 |
| 취향 | 오늘 기분 고르기 | 본인 입력, 공개 불필요 |
| 메뉴 | 추천 메뉴 마시기 | 직원 승인 |
| 누적 | 이번 달 아무 날이나 세 번 방문 | 방문 기록 |

- 조건, 보상, 기간, 진행 상태, 승인 대기, 완료·수령 상태를 표시한다.
- 반복 기본 퀘스트와 주간·계절 퀘스트를 섞어 매일 제작할 부담을 줄인다.
- 연속 출석 실패에 따른 손실, 장시간 체류, 타인과 교류, 프로필 공개를 보상 조건으로 삼지 않는다.
- 같은 퀘스트 반복 회차의 보상은 한 번만 지급한다.
- 기본 제안: 기간 내 서버에 완료 접수된 건은 승인 대기 중 종료되더라도 승인 가능하다. 기간 종료 후 신규 접수는 받지 않는다.
- 진행 중 퀘스트의 조건·보상 변경은 기존 접수에 소급하지 않는다. 변경분은 새 버전 또는 다음 회차부터 적용한다.
- 품절 시 운영자가 즉시 신규 참여를 중단하고 대체 퀘스트를 제공할 수 있다.
- 주문 후 퀘스트를 발견해도 같은 영업일의 검증 가능한 주문이면 인정하는 것을 제안한다. 검증 수단은 운영 정책과 함께 확정한다.

### 4.5 코인·아이템

- 단일 비현금성 코인을 사용하며 지급·사용·조정 원장을 남긴다.
- 코인 획득, 가격, 보유 아이템, 착용·해제를 제공한다.
- 첫 방문에 작은 아이템 하나를 얻을 수 있게 하고, 일반 방문 몇 차례 안에 다음 구매가 가능하도록 조정한다.
- 초기 아이템은 약 10종. 모자, 컵, 액세서리 등 매장 고유 소품을 활용한다.
- 초기에는 같은 아이템 중복 구매를 허용하지 않는다.
- 잔액 검증, 차감, 아이템 지급을 하나의 거래로 처리한다. 중복 요청·동시 구매에도 일관성을 유지한다.
- 가격 변경은 기존 구매에 소급하지 않는다. 판매 종료 후에도 보유 아이템은 유지한다.
- 코인 만료는 MVP에 도입하지 않는다. 기간 한정 판매는 명확한 종료 시각을 표시한다.
- 현금성 가치·양도·확률형 판매는 MVP에 없다.

### 4.6 다른 손님과 공개 범위

| 항목 | 기본값 | 규칙 |
| --- | --- | --- |
| 맵 노출 | 비공개 | 명시적으로 켜야 노출 |
| 닉네임·캐릭터 | 맵 공개 시 공개 | 공개 전 미리보기에서 안내 |
| 음료 | 비공개 | 방문별 본인 선택 |
| 활동 | 비공개 | 독서·작업·수다·휴식 등 선택형 |
| 실제 좌석 | 미연결 | 별도 선택, 노출 위험 안내 |
| 교류 상태 | 표시 안 함 | 혼자 쉬는 중·인사 좋아요 등 선택형 |

- 다른 손님 정보는 유효한 방문 세션을 가진 손님에게만 제공한다. 외부 링크로 공개 명단을 열람할 수 없게 한다.
- 공개 미리보기, 항목별 변경, 한 번에 숨기기를 제공한다.
- 비공개 필드는 다른 손님 대상 API·실시간 이벤트에서도 제외한다. 화면에서만 숨기지 않는다.
- 재접속, 캐시, 구독 갱신에서도 철회된 정보를 다시 노출하지 않는다.
- 공개 여부는 방문마다 확인한다. 이전 선호는 기억할 수 있으나 새 체류는 자동 공개하지 않는다.
- 음료·활동은 방문 종료 시 초기화한다. ‘오늘 고른 음료’와 ‘직접 설정한 상태’로 표현한다.
- 과거 방문 시각·이력, 주문 전체 내역, 실제 이름·연락처는 다른 손님에게 공개하지 않는다.
- 작은 매장에서는 조합된 정보로 실제 사람이 특정될 수 있음을 공개 선택 화면에서 짧게 안내한다.
- 공개 철회는 향후 서비스 노출을 중단한다. 상대가 이미 본 정보나 촬영한 화면까지 회수할 수 있다는 약속은 하지 않는다.
- 부적절한 닉네임·프로필 신고와 차단을 제공한다. 차단된 계정 간에는 손님 카드를 서로 숨긴다.

### 4.7 직원·운영자

- 퀘스트 생성·예약·중단, 반복 주기·기간·보상·확인 방식 설정.
- 아이템·가격·판매 상태 관리.
- 손님 확인 코드로 구매 퀘스트 승인. 주문 항목의 중복 인정 방지.
- 승인 대기 상태를 손님에게 표시하며 반복 요청으로 알림이 누적되지 않게 한다.
- 승인, 코인 조정, 이용 제한에 담당자와 사유를 기록한다.
- 잘못된 지급·환불 관련 보상은 원장을 지우지 않고 조정 거래로 처리한다.
- 이미 사용한 보상은 자동으로 음수 처리하지 않고 운영자가 확인한다.
- 부적절한 프로필 숨김·신고 처리와 이용 제한.
- 현재 체류, 기본 참여 지표, 장애 후 보상 누락 처리 제공.
- 직원 확인은 찾기부터 승인까지 약 5초를 파일럿 목표로 한다. 실제 측정 후 조정한다.

## 5. 운영 예외와 정책

| 상황 | 기본 처리 / 남은 결정 |
| --- | --- |
| QR 사진·방문 코드 공유 | QR만으로 보상 불가. 코드 공유 위험은 남으므로 낮은 보상·시도 제한·모니터링. 인증 수단 확정 필요 |
| 같은 날 재입장 | 체류 재시작, 방문 기본 보상 중복 불가 |
| 자정·야간 영업 | 한국 시간 기준 영업일 사용. 날짜 전환 시각은 영업시간 확인 후 확정 |
| 단체 주문·여러 잔 | 방문 보상은 계정별. 구매 보상은 검증된 항목별로 한 번, 동행자 배분 정책 확정 필요 |
| 취소·환불 | 관련 보상 표시 후 운영자 조정. 이미 사용한 코인·아이템 회수 정책 사전 고지 |
| 주문 뒤 퀘스트 발견 | 같은 영업일의 검증 가능한 주문을 인정하는 안. 확인 수단 확정 필요 |
| 품절·임시 휴무 | 퀘스트 신규 접수 중단, 미처리 접수 안내, 필요 시 대체 보상 |
| 승인 전 퀘스트 종료 | 기간 내 접수 건은 승인 가능, 중복·부정 여부 검증 유지 |
| 보상·구매 중 통신 단절 | 서버 거래 결과 조회 후 복원. 클라이언트 재시도로 중복 처리하지 않음 |
| 전체 서비스 장애 | 실제 카페 주문을 막지 않음. 최소 식별자로 누락을 접수해 복구 후 조정, 중복 지급 방지 |
| 유령 손님 | 유효 시간 만료 시 숨김. 체류는 실제 재실 보장 아님 |
| 실제 매장은 만석, 맵은 비어 있음 | 공개 참여 인원과 혼잡도 분리. 좌석 판단에 사용하지 않도록 안내 |
| 여러 기기·탭·계정 | 계정별 체류 하나, 거래 중복 방지. 다계정 남용은 비례적인 제한으로 대응 |
| 계정 데이터 삭제·기기 변경 | 연결 계정으로 복구. 미연결 게스트의 제한 안내 |
| 미성년자 참여 | 대상 연령·계정 제공자 요건 확인. 필요한 동의·처리 방침을 출시 전 확정 |
| 손님이 없거나 공개를 모두 거부 | 개인 퀘스트와 꾸미기만으로 이용 가능 |

연속 출석 손실과 체류 시간 비례 보상은 도입하지 않는다. 장시간 체류 유도는 카페 좌석 운영과 충돌할 수 있다.

## 7. 데이터와 품질 요구사항

주요 개념: 사용자·인증 연결, 캐릭터·아이템 소유, 방문 기록, 체류 세션, 공개 설정, 퀘스트 정의·회차·접수·완료, 코인 거래, 구매, 직원 승인·조정 감사 기록, 신고·차단.

- 체류 만료·공개 권한·잔액·보상 조건은 서버에서 판단한다.
- 사용자에게 보이는 시간은 Asia/Seoul, 내부 시각은 일관된 기준으로 저장한다.
- MVP에서 실제 좌석·활동을 상시 추적하지 않는다. GPS·백그라운드 위치 수집은 요구하지 않는다.
- 운영 지표에 공개 프로필 본문을 불필요하게 복제하지 않는다.
- 로그에 인증 코드·토큰·개인정보가 남지 않게 한다.
- 체류·감사·거래·신고 기록의 보관 기간과 삭제·익명화 정책은 출시 전 확정한다.
- iOS Safari, Android Chrome의 모바일 화면·터치·글자 확대를 지원한다.
- 상태를 색상만으로 구분하지 않는다. 맵 외 목록에서도 주요 기능에 접근 가능해야 한다.
- 목표: 체크인·퇴장·공개 변경이 연결된 다른 화면에 5초 이내 반영. 연결 단절 시 갱신 지연을 표시하고 재연결 시 전체 권한을 재검증한다.
- 명시적 퇴장·철회는 캐시와 실시간 구독에서도 제거한다. 만료된 사용자를 조회 결과에 포함하지 않는다.
- 목표: 중급 모바일·일반 모바일 네트워크에서 핵심 화면 조작 가능까지 3초 이내. 측정 조건과 동시 접속 목표는 개발 전 확정한다.
- 운영자 권한, 접근 제어, 요청 제한, 데이터 백업·복구를 출시 검증에 포함한다.

## 8. 파일럿과 성공 지표

단일 카페에서 2~4주 시험 운영한다. 수치 목표는 방문 규모와 기준 데이터를 확인한 뒤 확정한다.

| 지표 | 정의 / 해석 |
| --- | --- |
| 첫 퀘스트 완료율 | 신규 인증 참여자 중 첫 퀘스트를 완료한 비율 |
| 7일·30일 재참여율 | 관찰 기간이 지난 참여자 중 다른 영업일에 재인증한 비율 |
| 첫 구매·착용률 | 참여자 중 아이템을 구매하고 착용한 비율 |
| 공개 참여율 | 인증 방문 중 명시적으로 공개를 선택한 비율. 높이도록 강요하지 않음 |
| 직원 승인 시간 | 조회부터 승인까지의 중앙값과 지연 사례 |
| 운영 부담 | 교대별 문의·수동 조정·콘텐츠 관리 시간 |
| 오류 | 중복 지급, 잔액 불일치, 공개 철회 지연, 보상 누락 |

웹 재참여는 실제 방문 증가와 동일하지 않다. 계절·행사·기존 방문 습관을 고려하고 손님 인터뷰로 재방문 동기를 함께 확인한다. 2주 파일럿만으로 30일 재참여율을 판단하지 않는다.

## 11. 후속 확장

수신 동의형 응원·반응, 손님 전체 공동 퀘스트, 계절 맵·한정 컬렉션, 개인 테이블 꾸미기, POS 연동, 다지점 컬렉션을 검토한다.

반응은 받기 끄기·차단·횟수 제한을 먼저 설계한다. 읽음·응답 의무나 교류 보상을 넣지 않는다. 콘텐츠는 색상 변형·실제 매장 변화·계절 자산을 재사용해 운영 비용을 관리한다.
