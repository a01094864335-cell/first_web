# Cafe Quest — 제품 요구사항

- 버전: v0.3
- 갱신일: 2026-11-17 (Asia/Seoul)
- 상태: 기획 결정 반영, 구현 전
- 대상: 단일 오프라인 카페의 모바일 웹서비스
- 이름: Cafe Quest는 가칭

## 1. 목표와 완료 범위

실제 카페를 닮은 맵에서 캐릭터로 머물고, 방문 퀘스트로 웹 코인을 모아 꾸미기를 즐긴다. 원하는 정보만 다른 손님에게 공개한다. 오프라인 종이 스탬프는 웹으로 옮기되 온라인 게임 재화와 분리한다.

현재 문서에 기획된 기능 전체가 실제로 연동되어 동작하는 것을 개발 완료 목표로 한다. 단계는 구현 순서이며 기능 축소나 목업으로의 대체를 의미하지 않는다.

- 카페 고유의 공간·메뉴·계절 변화를 수집과 탐색의 즐거움으로 연결한다.
- 공개나 교류를 강요하지 않는다. 손님이 없어도 개인 경험을 즐길 수 있다.
- 직원의 추가 업무를 최소화하고 매장에서 유연하게 처리할 일을 과도하게 규칙화하지 않는다.
- 웹 퀘스트를 많이 수행해도 실물 보상 비용이 발생하지 않는다.

자유 채팅, 친구·팔로우, 공개 방문 이력, 경쟁 순위, 현금 구매·환전·양도, POS 자동 연동, 좌석 예약, 3D, 다지점 운영은 현재 범위 밖이다. 반응·공동 퀘스트·개인 공간은 후속 확장이다.

## 2. 핵심 사용자 흐름

| 사용자 | 흐름 |
| --- | --- |
| 매장 참여 손님 | 종이 QR 접속 → 캐릭터 생성·복원 → 자동 체크인 → 공개 선택 → 맵·퀘스트 → 보상 → 구매·꾸미기 |
| 원격 참여 손님 | 일반 접속 → 반투명 캐릭터로 참여·공개 선택 → 맵 구경·퀘스트 미리보기·꾸미기·보유 코인 사용 |
| 스탬프 적립 손님 | 카카오 로그인 → 내 적립 QR 제시 → 직원 스캔·수량 입력 → 적립 |
| 무료 음료 사용 손님 | 내 스탬프 → 사용 버튼 → 차감 확인 → 10개 차감·사용 완료 화면 |
| 코인 전환 손님 | 내 스탬프 → 전환량·수령 코인 확인 → 스탬프 차감·코인 지급 |
| 직원 | 적립 QR 스캔·수량 입력, 구매 퀘스트 승인, 사유를 남기는 거래 조정 |

## 3. 계정과 저장

- 백엔드 서버와 DB를 사용한다. 코인·스탬프·아이템·퀘스트·계정의 기준 데이터는 서버에 저장한다.
- 브라우저는 세션 식별·설정·캐시에 사용한다. 로컬 저장만으로 운영하지 않는다.
- 게스트로 닉네임·기본 캐릭터를 만들고 맵·퀘스트를 이용할 수 있다.
- 게스트 진행도 서버 저장하며 같은 브라우저에서 이어간다. 미연결 게스트는 브라우저 데이터 삭제·기기 변경 시 복구에 제한이 있음을 안내한다.
- 사용자 로그인은 카카오만 제공한다. 첫 계정 연결 시 게스트의 코인·아이템·진행도를 보존한다.
- 스탬프 첫 적립과 종이 카드 이전에는 카카오 로그인이 필요하다. 스탬프는 카카오 연결 계정에 보관한다.
- 연결 대상 카카오 계정에 이미 데이터가 있을 때의 병합·선택 규칙은 미정이다. 자동 합산이나 폐기를 확정하지 않는다.
- 닉네임과 내부 식별자를 분리한다. 닉네임은 중복될 수 있다.
- 로그아웃·탈퇴·데이터 처리 안내와 연결 계정 복구 경로를 제공한다.
- 운영자 인증·권한은 손님과 분리하며 구체적 방식은 별도 결정한다.

## 4. 카페 맵과 이동

- 실제 사진·평면도를 반영한 탑다운 2D 픽셀 타일맵. 선택한 그린 라운지 시안의 우드 바닥·그린 가구·작은 캐릭터 애셋을 기준으로 한다.
- 원하는 지점을 터치하면 캐릭터가 경로를 따라 걸어간다. 벽·가구는 통과하지 않는다.
- 공개 캐릭터의 이동·착용 변경을 다른 참여자에게 동기화한다.
- 출입구·카운터·창가·테이블·식물 등과 퀘스트 오브젝트를 배치한다.
- 기본 캐릭터 위치는 실제 좌석과 무관하다. 실제 좌석 연결은 별도 선택이며 예약·점유를 보장하지 않는다.
- 맵 외 목록에서도 손님·퀘스트 등 주요 기능에 접근할 수 있다.
- 혼잡 시 구역별 묶음·목록으로 겹침을 줄인다.
- ‘맵 참여 중 N명’으로 표시한다. 실제 매장 손님 수·혼잡도로 해석되지 않게 한다.

## 5. 종이 QR 입장·원격 모드·체크아웃

### 5.1 참여 모드

| 기능 | 매장 모드 | 원격 모드 |
| --- | --- | --- |
| 진입 | 매장 종이 QR 링크 접속 | 일반 접속 |
| 캐릭터 | 일반 표시 | 반투명 + 원격 표시 |
| 맵 탐색·공개 손님 보기 | 가능 | 가능 |
| 퀘스트 목록·보상 미리보기 | 가능 | 가능 |
| 퀘스트 시작·진행 | 가능 | 불가 |
| 꾸미기·보유 코인으로 상점 구매 | 가능 | 가능 |

- 종이 QR 하나로 운영한다. 코드 입력, 직원 방문 승인, QR 갱신용 화면은 요구하지 않는다.
- QR 접속 시 자동 체크인한다. 처음에는 캐릭터 생성 절차를 거친다.
- QR 주소를 저장·공유하면 매장 밖에서도 매장 모드에 진입할 수 있음을 수용한다.
- 날짜별 리다이렉트도 저장된 고정 QR 주소의 외부 사용을 막지 못한다. 동적 링크는 인증 수단이 아니며 필수 기능이 아니다.
- 매장 모드는 QR을 통한 참여 상태이며 실제 위치·구매 인증을 의미하지 않는다. 지표에서도 물리적 방문 확정치로 취급하지 않는다.
- 기본 방문 보상은 계정·매장·영업일당 한 번, 웹 코인으로만 지급한다. 재입장으로 추가 지급하지 않는다.
- 원격 무료 음료 사용·스탬프 전환 허용 범위는 별도 결정이 필요하다. 앞선 화면 제안의 제한을 확정 정책으로 취급하지 않는다.

### 5.2 체류와 종료

- 계정당 활성 참여 세션은 하나이며 여러 탭·기기는 상태를 공유한다.
- 매장 체류는 90분. 만료 전 이용 중인 화면에서 ‘아직 카페에 계신가요?’로 명시적 연장을 받는다.
- 연장 시간은 같은 90분을 사용하는 운영 기본값으로 두며 조정 가능하게 한다.
- 웹 종료·백그라운드·화면 잠금·연결 단절만으로 즉시 퇴장하지 않는다.
- 클릭·네트워크 연결만으로 자동 연장하지 않는다. 백그라운드 알림 도착에 의존하지 않는다.
- 미연장 만료 시 서버에서 매장 모드·퀘스트 진행 권한을 종료하고 공개를 숨긴다.
- 이후 원격 상태로 전환 안내하며 계속 공개할지는 다시 확인한다. 자동으로 원격 공개를 유지하지 않는다.
- 직접 나가기·운영자 종료·영업 종료 시에도 매장 상태와 공개를 종료한다.
- 재접속 시 서버 상태를 복원하고, 매장 모드 재입장은 QR로 진행한다.
- 만료 시각을 실제 퇴장 시각으로 기록·표현하지 않는다. 원격 비활성 종료 기준은 미정이다.

## 6. 퀘스트

| 유형 | 예시 | 확인 |
| --- | --- | --- |
| 방문 | 오늘 카페 참여 | QR 매장 모드 체크인 |
| 탐색 | 새 화분 찾기 | 맵 오브젝트 선택 |
| 취향 | 오늘 기분 선택 | 본인 입력, 공개 불필요 |
| 메뉴 | 추천 메뉴 맛보기 | 직원 승인 |
| 누적 | 이번 달 아무 날이나 세 번 방문 | QR 참여 기록 |

- 매장 모드에서만 시작·진행한다. 원격에서는 목록·조건·보상만 구경한다.
- 매장 모드 종료 시 진행을 멈추고 기존 진행도는 보존한다. 원래 퀘스트 기한은 유지한다.
- 이미 완료한 퀘스트 보상을 원격에서 수령할 수 있게 하는 안은 별도 확정 전이다.
- 구매 퀘스트는 QR 참여와 별개로 직원 확인을 유지한다.
- 조건·기간·보상·진행도·승인 대기·완료·수령 상태를 표시한다.
- 반복 기본 퀘스트에 주간·계절 퀘스트를 섞는다. 운영자가 생성·예약·중단할 수 있다.
- 보상은 웹 코인·디지털 아이템이다. 스탬프나 무료 음료를 퀘스트로 지급하지 않는다.
- 연속 출석 실패 손실, 장시간 체류, 타인과 교류, 공개 설정을 보상 조건으로 삼지 않는다.
- 같은 회차의 보상은 한 번만 지급한다. 주문 항목의 중복 승인도 막는다.
- 기간 내 접수된 승인 대기 건은 기간 종료 후 승인 가능하게 하는 안을 기본으로 둔다.
- 진행 중 조건·보상 변경은 기존 접수에 소급하지 않고 새 버전·회차부터 적용한다.
- 품절·휴무 시 신규 참여를 중단하고 대체 또는 종료 상태를 안내한다.
- 주문 후 퀘스트 발견 시 같은 영업일의 검증 가능한 주문을 인정하는 안을 기본으로 두되, 검증 수단은 확정해야 한다.

## 7. 웹 코인과 아이템

- 웹 코인과 매장 스탬프는 별도 잔액·원장으로 관리한다.
- 코인은 퀘스트 또는 스탬프 전환으로 획득하며 온라인 꾸미기에만 사용한다.
- 코인을 스탬프·음료·현금으로 역전환하지 않는다. 양도·현금 구매·확률형 판매도 현재 범위 밖이다.
- 상점 목록·가격·판매 기간·미리보기·구매·보유·착용·해제를 제공한다.
- 초기 모자·컵·소품 등 약 10종을 출발점으로 삼되 전체 기능 범위를 제한하지 않는다.
- 첫 방문에도 작은 아이템을 얻고 몇 차례 방문 안에 다음 구매가 가능하도록 밸런스를 검토한다. 최종 수치는 아직 정하지 않는다.
- 같은 아이템 중복 구매 불가. 가격 변경은 기존 구매에 소급하지 않는다.
- 판매 종료 후에도 보유 아이템은 유지한다. 코인 만료는 도입하지 않는다.
- 잔액 검증·차감·아이템 지급은 하나의 거래로 확정한다. 재시도·동시 요청에도 중복·음수 잔액이 없어야 한다.

## 8. 스탬프·무료 음료·전환

### 8.1 적립과 종이 카드 이전

- 유료 구매 음료 한 잔당 스탬프 1개 적립한다.
- 무료 교환 음료에는 적립하지 않는다. 스탬프 유효기간은 없다.
- 카카오 로그인 손님이 내 적립 QR을 보여주면 직원이 관리자 화면에서 스캔하고 유료 구매 잔 수를 입력한다.
- 적립 QR은 계정 식별용이다. 직원 권한 없이 적립할 수 없다.
- 종이 스탬프는 같은 적립 기능에서 사유 ‘종이 카드 이전’으로 수량을 입력한다.
- 종이 카드는 확인 후 회수하거나 이전 완료 표시해 중복 사용을 막는다. 여러 카드 합산·동행자별 배분은 매장 운영으로 처리한다.

### 8.2 무료 음료 사용

- 스탬프 10개로 모든 음료 중 원하는 1잔을 무료로 제공한다.
- 손님 폰에서 ‘무료 음료 사용’을 눌러 진행한다. 직원 스캔을 사용 승인 필수 조건으로 두지 않는다.
- 차감 확인 → 서버 잔액 검증·10개 차감 → 사용 완료·시각 표시 흐름으로 구성한다.
- 완료 화면의 움직이는 표시 등으로 과거 화면 재사용을 줄이고 서버 사용 기록·거래 식별자를 남긴다. 화면만으로 진위가 보장된다고 약속하지 않는다.
- 반복 클릭·네트워크 재시도·다중 기기에도 같은 요청을 중복 차감하지 않는다.

### 8.3 스탬프 → 웹 코인

- 전환할 스탬프를 차감하고 웹 코인을 지급한다. 역전환 불가.
- 전환량·차감 후 스탬프·수령 코인을 확인한 뒤 확정한다.
- 전환 비율과 단위는 애셋 가격·퀘스트 난이도·보상량을 검토하고 가장 마지막에 결정한다. 임의 비율로 실제 전환을 운영하지 않는다.
- 스탬프 차감과 코인 지급을 하나의 거래로 처리한다. 무료 음료 사용·전환·직원 조정 간 동시성도 검증한다.

### 8.4 취소·조정

- 직원은 사유를 남겨 잘못된 적립이나 취소 주문의 적립을 되돌릴 수 있다.
- 이미 사용된 스탬프가 있으면 자동 음수 차감 대신 별도 확인한다.
- 원래 거래를 삭제하지 않고 연결된 조정 거래와 담당자·사유를 남긴다.
- 사용된 스탬프·코인·아이템의 구체적 회수·고지 절차는 별도 확정한다.

## 9. 다른 손님과 공개 범위

| 항목 | 기본값 | 규칙 |
| --- | --- | --- |
| 맵 노출 | 비공개 | 매장·원격 모두 본인이 켜야 노출 |
| 닉네임·캐릭터 | 공개 참여 시 공개 | 미리보기에서 안내 |
| 음료 | 비공개 | 방문별 직접 선택 |
| 활동 | 비공개 | 독서·작업·수다·휴식 등 선택 |
| 실제 좌석 | 미연결 | 별도 선택, 노출 위험 안내 |
| 교류 상태 | 표시 안 함 | 혼자 쉬는 중·인사 좋아요 등 |

- 유효한 참여 세션의 매장·원격 사용자 모두 공개 참여 손님을 볼 수 있다. 외부 공개 명단은 제공하지 않는다.
- 반투명뿐 아니라 ‘원격’ 표시도 함께 사용한다.
- 항목별 변경·미리보기·한 번에 숨기기·신고·차단을 제공한다.
- 비공개 항목은 다른 손님 대상 API·실시간 이벤트에서도 제외한다.
- 공개 철회는 목록·캐시·구독·재연결에도 반영한다.
- 새 방문에는 공개를 다시 확인하며 이전 선호만 기억할 수 있다. 만료 후 원격 공개도 재확인한다.
- 음료·활동은 방문 종료 시 초기화한다. ‘오늘 고른 음료’, ‘직접 설정한 상태’로 표현한다.
- 과거 방문 이력·시각, 주문 전체, 실제 이름·연락처, 스탬프·거래 내역은 다른 손님에게 제공하지 않는다.
- 작은 매장에서는 조합된 공개 정보로 실물이 특정될 수 있음을 짧게 안내한다.
- 이미 본 정보나 촬영한 화면까지 회수할 수 있다는 약속은 하지 않는다.
- 차단 계정 간 손님 카드는 서로 숨긴다. 운영자는 부적절한 프로필을 숨기고 이용 제한할 수 있다.

## 10. 직원·운영자 기능

- 운영자 로그인·권한 분리, 기본 참여·승인 대기·오류 지표.
- 퀘스트 생성·예약·수정·반복·기간·보상·중단 관리.
- 아이템·가격·판매 기간·판매 상태 관리.
- 손님 코드로 구매 퀘스트 확인·승인, 주문 항목 중복 방지. 손님에게 승인 대기를 표시한다.
- 손님 QR 스캔·스탬프 적립·종이 카드 이전·사용 기록 조회·적립 취소.
- 코인·스탬프 원장 구분, 전환 거래 연결, 오지급·환불·누락 조정.
- 참여 세션 종료, 신고 처리, 프로필 숨김·이용 제한.
- 승인·조정·제한의 담당자·사유·시각 감사 기록.
- 직원 확인은 찾기부터 승인까지 약 5초를 목표로 파일럿에서 측정한다.

## 12. 운영 예외와 품질 요구사항

- QR 외부 사용은 수용하되 스탬프 적립은 직원 권한으로 분리한다. QR 체크인을 구매·실제 방문 검증으로 사용하지 않는다.
- 같은 날 재입장에 기본 방문 보상을 중복 지급하지 않는다. 영업일은 한국 시간 기준이며 전환 시각은 영업시간 확인 후 결정한다.
- 품절·휴무·퀘스트 종료·승인 대기·보상 거절 상태를 분리한다.
- 네트워크 단절 시 거래 결과를 재조회해 복원한다. 미확정 거래를 성공으로 보여주지 않는다.
- 장애가 실제 카페 주문을 막지 않아야 한다. 최소 식별자로 누락을 접수해 복구 후 조정하고 중복 지급을 막는다.
- 체류·모드·이동·공개 권한·잔액·보상 검증은 서버가 수행한다.
- 데이터 개념: 사용자·카카오 연결, 캐릭터·소유·착용, QR 참여 기록, 모드·체류·이동, 공개 설정, 퀘스트 회차·진행·승인, 코인·스탬프 원장·무료 음료 사용·전환, 신고·차단·감사 기록.
- GPS·백그라운드 위치 수집은 요구하지 않는다. 최소 정보만 수집하고 로그에 토큰·QR 식별값·개인정보를 노출하지 않는다.
- 거래·체류·신고·감사 기록의 보관·삭제·익명화 기간과 대상 연령 정책은 출시 전 확정한다.
- iOS Safari·Android Chrome, 터치·글자 확대·목록 대체 접근을 지원한다. 색상·투명도만으로 상태를 구분하지 않는다.
- 체크인·퇴장·공개 변경은 연결 화면에 5초 내 반영을 목표로 한다. 이동 갱신 주기·예상 동시 접속 수는 기술 설계에서 확정한다.
- 연결 지연을 표시하고 재연결 시 상태·권한을 다시 검증한다. 만료된 매장 공개를 유지하지 않는다.
- 중급 모바일·일반 모바일 네트워크에서 핵심 화면 조작 가능까지 3초를 목표로 하며 측정 조건은 개발 전 확정한다.
- 권한 검증·요청 제한·거래 동시성·백업·복구를 출시 검증에 포함한다.

## 13. 검증과 운영 지표

- [ ] QR → 자동 체크인 → 매장 퀘스트 → 코인 → 구매 → 착용을 실제 모바일에서 완료.
- [ ] 일반 접속은 반투명 원격 상태이며 퀘스트 시작·진행 불가.
- [ ] 터치 경로·가구 충돌·다른 사용자 이동 동기화 확인.
- [ ] 두 사용자가 서로 공개한 정보만 보고 철회·차단·재연결에도 권한 유지.
- [ ] 90분 만료·명시적 연장·직접 퇴장·영업 종료·원격 공개 재확인 검증.
- [ ] 웹 종료·화면 잠금으로 즉시 퇴장하지 않고 서버 상태 복원.
- [ ] 서버 게스트 복원·카카오 연결·데이터 보존·충돌 처리 검증.
- [ ] 스탬프 적립·이전에 로그인 필수, 직원 QR 적립과 종이 카드 이전 기록 확인.
- [ ] 유료 한 잔당 1개, 무료 음료 적립 없음, 10개로 모든 음료 중 1잔, 유효기간 없음 확인.
- [ ] 손님 폰 무료 음료 사용·완료·다중 요청 중복 차감 방지.
- [ ] 확정된 전환 비율로 스탬프 차감·코인 지급 원자성, 역전환 불가 검증.
- [ ] 구매·전환·사용·조정의 동시 실행에도 중복 지급·음수 잔액 없음.
- [ ] 재입장·영업일 전환·품절·승인 대기 중 종료·오승인·이미 사용한 적립 취소 검증.
- [ ] 타인의 거래·운영자 기능 접근 차단, 신고·탈퇴·로그·백업 복구 검증.
- [ ] 통신 단절·서버 장애 후 거래 복원·누락 처리 검증.
- [ ] 붐비는 시간 신규 두 명·단골 한 명·바쁜 직원 운영 리허설.

전체 기능 검증 후 단일 매장에서 2~4주 시험 운영한다. 첫 퀘스트 완료율, QR 재참여율, 구매·착용률, 공개 선택률, 직원 처리 시간, 수동 조정·문의·오류를 측정한다. 공개율을 높이도록 강요하지 않는다.

QR 재참여는 실제 방문 증가와 동일하지 않다. 행사·계절·기존 습관과 인터뷰를 함께 본다. 30일 지표는 관찰 기간이 지난 사용자만 집계한다.

## 15. 후속 확장

수신 동의형 응원·반응, 공동 퀘스트, 계절 맵·컬렉션 확대, 개인 테이블·공간, POS·다지점 연동. 반응은 받기 끄기·차단·횟수 제한부터 설계하며 읽음·응답 의무나 교류 보상을 넣지 않는다. 애셋 재사용으로 지속 운영 비용을 관리한다.
