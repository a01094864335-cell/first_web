## 4. 안전하게 먼저 진행할 수 있는 작은 개선

1. **문서 상태 정리:** README의 ‘로그아웃 미구현’ 문구는 현재 로그아웃 구현과 상충한다. 기존 ‘CSS 캐릭터’ 문구도 런타임 통합이 끝나면 실제 검증 결과에 맞춰 갱신한다.
2. **캐릭터 로딩 상태:** 기존 캐릭터를 즉시 숨기는 대신 새 파츠 준비 후 교체, 실패하면 이전 외형 유지. 선택한 조합/동작만 미리 읽기.
3. **회차·권한 안내:** 미완료/승인 대기/완료 보상/원격 잠금을 각 화면에서 같은 문구로 표현한다.
4. **공개 정보 미리보기:** 현재 공개한 활동/음료를 손님 카드 모양으로 보여주되 미연결 실제 좌석은 추정하지 않는다.
5. **운영 상태 표시:** 공개 시연에는 목/서버 모드와 버전 표시를 고정하여 실제 운영 기능과 혼동하지 않게 한다.

## 5. 입력/승인이 있어야 열 수 있는 운영 항목

- 실제 카카오 앱 설정·등록된 리다이렉트·비밀값과 초기 운영자 계정. 저장소에 비밀값을 넣지 않는다.
- 실제 스탬프 전환 비율과 단위, 카페 영업시간, 개인정보 보관·삭제·연령 정책.
- 운영 인프라 비용·호스팅과 별도 배포 승인. PR 작성/푸시는 main 머지나 운영 배포 승인이 아니다.
- 실제 고객/직원 데이터로 검증할 시나리오와 파일럿 범위.

자격증명이 없는 동안 외부 연동은 격리된 목으로 유지한다. 미결정 항목 때문에 독립적인 UI/테스트/콘텐츠 작업까지 중단할 필요는 없지만, 목 결과를 실제 연동 완료로 보고하지 않는다.

## 6. 검증 기록 경계

기존 `IMPLEMENTATION.md`의 Python 56개, client/demo/DOM 통과는 이전 체크포인트 기록이다. 로컬 Chromium 접속 실패 기록과 이후 공개 Site v1의 CUA 온보딩·맵 성공 기록은 서로 다른 환경/범위의 결과이며, 전자가 후자의 전체 실패를 뜻하거나 후자가 운영 E2E 완료를 뜻하지 않는다. PR #3의 5,712개 파츠 포즈 및 204개 중복 idle 정적 검사는 애셋 검사이지 모든 조합·브라우저·게임 통합 검사 결과가 아니다. 이번 인벤토리 작성에서는 문서/코드를 검토했으며 최종 통합 테스트는 아직 실행하지 않았다. 완료 후 정확한 커밋과 실행 명령·성공/실패/미실행 항목을 별도 기록한다.

## 7. 통합 검증 결과 (2026-11-19)

65 Python tests, client/demo API, avatar demo contracts, 실제 adapter 구조 테스트, 확장 DOM flows, 원본 viewer helpers, 1,015 atlas 검사가 통과했다. DOM 테스트는 renderer를 mock하고 adapter 테스트는 Canvas/Image를 double로 사용한다.

별도 실제 CUA browser로 지원되는 내부 Sites preview를 열어 온보딩, 51파츠 옷장, 버즈컷·봄버·카고 조합, 앞방향 걷기, 저장, 맵 같은 외형, reload 복원, 뒤방향 인사 화면을 확인했다. 초기 runtime module404를 발견해 정적 허용 목록을 고쳤다. 이 범위는 전체 조합·모바일 실기기·운영 인증 검증이 아니다. 공개 Site v1은 변경하지 않았다.

리뷰에서 저장후 새로고침 실패 시 draft 역행, heartbeat의 열린 select 교체, 실패 이미지 재시도 캐시 문제를 수정하고 회귀 테스트했다.
